# Deploy

Production layout (Phase 9):

| Piece | Host | Notes |
|---|---|---|
| Frontend (Next.js) | Vercel | Root directory `frontend/` |
| Backend (FastAPI) | Render web service (Docker, free plan) | `render.yaml` Blueprint, image from `backend/Dockerfile` |
| Postgres | Neon (free) | Direct (non-pooler) endpoint |
| Redis | Upstash (free) | TLS (`rediss://`) |

Use the same region for all three back-end pieces (Render `singapore`, Neon `aws-ap-southeast-1`, Upstash `ap-southeast-1`), because every action request makes several round trips to Postgres and Redis.

Order matters: database → migrations → backend login → Redis → backend → frontend → CORS.

## 1. Postgres (Neon)

1. Create a Neon project (Postgres 16+) in `aws-ap-southeast-1`.
2. Copy the **direct** connection string (host without `-pooler`). PgBouncer's transaction mode breaks asyncpg's prepared statements. This string uses the owner role (`neondb_owner`). It's the **migration URL**, so keep it on your machine only.
   You can paste it as-is (`postgresql://…?sslmode=require&channel_binding=require`). The backend converts it to `postgresql+asyncpg://…?ssl=require` itself.
3. From `backend/`, run the migrations as the owner (PowerShell):
   ```powershell
   $env:MIGRATION_DATABASE_URL = "<neon owner URL>"
   .venv\Scripts\alembic upgrade head
   ```
   The last migration creates the NOLOGIN `aaf_app` role and its grants (ADR-009).
4. In the Neon SQL editor (as the owner), create the backend's login. Generate the password with `python -c "import secrets; print(secrets.token_urlsafe(32))"`:
   ```sql
   CREATE ROLE aaf_backend LOGIN PASSWORD '<password>' IN ROLE aaf_app;
   ```
5. The **app URL** is the owner URL with `aaf_backend:<password>` in place of the owner's credentials. Use it for everything from here on.

## 2. Redis (Upstash)

Create a Redis database in `ap-southeast-1` with TLS enabled, then copy the `rediss://default:<token>@<host>:6379` URL. The rate limiter's Lua script (ZADD/ZCARD/ZRANGE/ZREMRANGEBYSCORE/PEXPIRE) is supported by Upstash.

## 3. Seed data and operator accounts

Run these from `backend/` on your machine, using the **app URL**. Shell env vars override `backend/.env`.

```powershell
$env:DATABASE_URL = "<neon app URL (aaf_backend)>"
$env:REDIS_URL = "<upstash rediss:// URL>"
.venv\Scripts\python -m app.seed
.venv\Scripts\python -m app.manage create-approver <username>
.venv\Scripts\python -m app.manage issue-agent-key demo-email-agent
.venv\Scripts\python -m app.manage issue-agent-key demo-payments-agent
```

Store the printed agent keys somewhere safe, because they're shown only once. Close the shell afterwards, or `Remove-Item Env:DATABASE_URL, Env:REDIS_URL, Env:MIGRATION_DATABASE_URL`, so later local commands don't hit production.

## 4. Backend (Render)

1. Push the repo to GitHub. In Render, go to **New → Blueprint** and pick the repo. Render reads `render.yaml`.
2. Fill in the `sync: false` values:
   - `DATABASE_URL`: the **app URL** (never the owner URL; the startup guard refuses an owner or superuser login)
   - `REDIS_URL`: the Upstash URL
   - `CORS_ORIGINS`: `["https://<your-app>.vercel.app"]` (set it to a placeholder for now and fix it in step 6)
   - `GMAIL_*`, `STRIPE_SECRET_KEY`: the same values as in `backend/.env` (Stripe test key only, because live keys are refused). Check them locally with `python -m app.manage check-credentials`.
   - `JWT_SECRET` is generated by Render.
3. Once the deploy is live, `https://<service>.onrender.com/health` should return `{"status":"ok"}`. If the logs show `Refusing to start`, they say which setting is unsafe.

The image runs uvicorn with `--proxy-headers`. `FORWARDED_ALLOW_IPS` trusts only private and CGNAT address ranges, so the login throttle uses the client's real IP from `X-Forwarded-For`. **Never set it to `*`**: uvicorn would then trust the leftmost entry, which the client can forge, and that bypasses the per-IP throttle.

The free plan sleeps after 15 minutes of no traffic. The first request after that takes about a minute.

## 5. Frontend (Vercel)

1. Go to **Add New → Project**, import the repo, and set **Root Directory** to `frontend`. The framework preset is Next.js.
2. Add the env var `NEXT_PUBLIC_API_BASE_URL` = `https://<service>.onrender.com` (no trailing slash). It's inlined at build time, so redeploy after changing it.
3. Deploy, then note the production URL.

## 6. CORS

In Render, set `CORS_ORIGINS` to `["https://<your-app>.vercel.app"]` (the exact production origin). Render redeploys on save. Preview deployments use other origins, so they can't call the API, and that's intentional.

## 7. Production QA

- [ ] `GET /health` returns 200
- [ ] Dashboard loads; signing in with a wrong password gives 401, and the 11th rapid attempt gives 429
- [ ] Sign in as the approver; `/agents` lists both demo agents
- [ ] `POST /actions/request` with the email agent key → `allowed` → a real email arrives, and the event shows as `executed` in `/audit`
- [ ] A payment over $50 from the payments agent → `needs_approval` → approve in `/approvals` → Stripe test PaymentIntent created
- [ ] Exceed a rate limit → `denied` / `rate_limited`
- [ ] The Render log for a login shows the caller's public IP, not a `10.x` proxy address
- [ ] A request from a non-Vercel origin gets no `access-control-allow-origin` header

Example agent call:

```bash
curl -X POST https://<service>.onrender.com/actions/request \
  -H "X-API-Key: <email agent key>" -H "Content-Type: application/json" \
  -d '{"action_type":"send_email","payload":{"to":"you@example.com","subject":"Hello from prod","body":"It works."}}'
```

## Maintenance

- **Schema changes:** run `alembic upgrade head` with the owner URL *before* pushing code that needs the new schema. Every new table needs a GRANT to `aaf_app` in its migration.
- **Gmail token:** the OAuth app is in Testing mode, so the refresh token expires after about 7 days (`invalid_grant`). Re-run `python -m app.manage gmail-auth` and update `GMAIL_REFRESH_TOKEN` in Render. Publishing the OAuth app removes the expiry.
- **Rotating the DB password:** `ALTER ROLE aaf_backend PASSWORD '…'` in Neon, then update `DATABASE_URL` in Render.
